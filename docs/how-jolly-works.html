How Jolly works

The app reads your accounts and computes every figure in plain, tested code. Then an AI coach named Jolly explains the results. The diagrams below follow a request through the system: where data comes from, what runs, where the AI is allowed in, and what gets stored.

00Five rules every part of the system follows

Each diagram is a consequence of these rules. If something in the code looks odd, one of these is usually the reason. The section numbers point into CLAUDE.md.

  • §0.1The AI never computes a numberCode computes every figure. The model only explains them, and a check rejects any figure it invents.
  • §0.2Every figure shows its sourceEach result carries which accounts it used, when the data was fetched, and the math applied. The "why" cards display this.
  • §0.3Money is integer centsAmounts are stored as whole numbers of cents (bigint), never floats. One function does the conversion, on the server.
  • §0.4Never keep a copy Plaid already holdsBalances and transactions are fetched fresh for each request, then thrown away.
  • §0.6Questions map to fixed pipelinesThe AI picks which of six pipelines to run. It never chooses tools or calculations.

01System map

One shared core package does all the work. The web app and a local MCP server both call it, so neither duplicates any logic. Data reaches core through a snapshot that exists only in memory for the length of one request.

02One chat turn, start to finish

Every question repeats the whole trip: a fresh Plaid fetch, a routing call, a fixed pipeline, an answer, and a check on that answer. Nothing is cached between turns. The network panel under each answer shows this same sequence with real timings.

In the codeapps/web/src/app/api/chat/route.tsapps/web/src/server/agent.tspackages/core/src/agent/router.tspackages/core/src/trace.ts

03The figure guard: how a number reaches the screen

The AI may only repeat figures that the code has already formatted. The guard collects every dollar amount and percentage in the AI's draft and looks each one up in that set. Anything it can't match counts as either a hallucination or the AI doing its own math.

In the codepackages/core/src/agent/attribution.tspackages/core/src/present.tspackages/core/src/money.tspackages/core/src/provenance.ts

04Six workflows, each a fixed sequence

The router can only choose a row in this table; the steps in each row are fixed in code. If the router picks the wrong row, Jolly answers the wrong question, but every figure is still computed correctly. A question that spans two rows is answered from one, and Jolly says what that row doesn't cover.

In the codepackages/core/src/workflows/packages/core/src/compute/packages/core/src/tools/aggregation.ts

05What is stored, and how that is decided

One question settles whether any piece of data may be stored. It is designed to give the same answer whoever asks it.

06Document import Phase 2 · built

This is how real data arrives while Plaid stays in sandbox. The expensive work happens once, at import. After that, statement data is read from the ledger like any other source. No row reaches the ledger until a person has confirmed it.

07The playground Phase 3 · planned

Production runs all eight stages as one call with settings fixed in code. The playground calls the same functions one stage at a time. You can feed any stage your own input, change its prompt or model, and see what it passes on. It's gated by a flag, off in production, and never writes.

  • Editable per runPrompts and modelsRouter and Jolly system prompts, model, token limits, history windows, the retry message, and the PDF transcription prompt.
  • Editable per runInputs and datesAny stage's input; the snapshot (live, a fixture, or hand-edited); "now" for date resolution; FIRE parameters; CSV sign convention.
  • Shown, not editableThe structureThe six pipelines, the router's list of choices, the guard rules, and the exact evidence text the model receives.
  • NeverWrites or shortcutsNever writes a net-worth point, a ledger row or a stored file. Never commits a draft, never turns off a guard, never changes production at runtime.
